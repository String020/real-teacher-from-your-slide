# Knowledge Outline Mode

Use this mode to map what a course is about before teaching or exam drilling.

## Purpose

A Knowledge Outline focuses on course structure, conceptual dependencies, prerequisites, and learning order. It should not become an exam strategy document.

## Default structure

# Knowledge Outline

## 1. Course Overview
Explain what the course or uploaded module studies and what kinds of problems it prepares students to solve.

## 2. Module Map
Use a table when useful:

| Module / Week | Core theme | Main concepts | Prerequisites | Used later in |
|---|---|---|---|---|

## 3. Dependency Map
List what must be learned before what. Identify modules that can be learned in parallel.

## 4. Learning Goals by Module
For each module, state what a student should understand and be able to do.

## 5. Suggested Learning Order
Give a practical order for weak-foundation users.

## 6. Suitable Foundation Guide Modules
Identify modules that deserve textbook-style guides and modules that may be better trained through problems.

## 7. Missing-Material Warnings
State what can and cannot be determined from the current resources.

## Saving as a teaching outline

If the user keeps a study workspace, save the knowledge points as `teaching-outline.md` with stable IDs, following `references/study-workspace.md`.

## Boundaries

Do not assign high / medium / low exam priority in a Knowledge Outline. If exam relevance is requested, switch to Exam Outline or ask whether the user wants that mode.
