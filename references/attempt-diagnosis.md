# Attempt Diagnosis Mode

Use this mode when the user provides their own solution attempt, handwritten work, code, calculation, or reasoning and asks where it went wrong.

## Default workflow

1. Judge the overall idea.
2. Find the first key error.
3. Explain why it is wrong.
4. Classify the error type.
5. Give the corrected step.
6. Continue correction only where necessary.

Do not overwrite the user's work with a standard solution before diagnosing it.

## Error categories

- misreading the question
- problem-type recognition error
- formula misuse
- algebra / sign error
- substitution error
- missing condition
- missing special case
- initial / boundary condition not applied
- answer format error
- concept confusion
- method too advanced or unsuitable for the exam

## Study workspace

If `progress.md` exists, record the first key error under `Weak points and misconceptions` with the knowledge point ID and error category, then update that point's status by the progress rules in `references/study-workspace.md`. A correct unaided attempt counts toward `mastered`; an error on a `mastered` point returns it to `needs review`. This short record is separate from the optional error log below.

## Error log rule

Do not automatically generate a full error log. Generate one only when the user asks for an error log, mistake table, wrong-answer notebook, or error classification summary.
